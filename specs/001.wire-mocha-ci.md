# 001 — Wire mocha and CI to a repo with no real tests

## §1. Behaviour today

No test runner, no CI workflow. Three root-level files —
`test-pagination.js`, `test-balances-pagination.js`, `test-screener.js`
— are named like tests but contain zero assertions, `throw`s, or exit
codes; each just `console.log`s a hardcoded checklist ending in "✅ All
changes implemented" regardless of the code's actual state (§1.1,
confirmed by grepping all three for `assert|expect(|throw new
Error|process.exit` — no matches). They are not referenced from
`package.json`, `gulpfile.js`, or any CI (§1.2) — dead, misleading
clutter rather than coverage.

## §2. Desired behaviour

`npm test` runs a real mocha suite and exits 0 (§2.1). CI runs `npm
test` on every PR (§2.2). One placeholder spec proves the wiring is
real until actual coverage lands (§2.3). The three fake "test" files are
removed — keeping them next to real tests would make it look like this
repo has more coverage than it does (§2.4).

## §3. Open questions / assumptions

- §3.1 mocha + chai was the default choice for this task's brief, but
  this repo's package.json `"overrides"` globally pin `minimatch` to
  `3.1.5` (for an unrelated dependency's compatibility/security reason)
  — that cascades into mocha's own bundled `glob@10.5`, which needs a
  modern minimatch, and breaks it (`TypeError: hasMagic is not a
  function`, confirmed by reproducing directly with `npx mocha`, with
  and without ts-node's `--extension` flag). Switched to Node's built-in
  `node:test` runner instead — no such dependency, no conflict — rather
  than touching the pinned overrides, which exist for a reason unrelated
  to this change.
- §3.2 Removing the three fake files is judged in-scope, not scope
  creep: this task is specifically about establishing real test
  infrastructure, and files that impersonate tests without checking
  anything directly undermine that goal if left in place.
